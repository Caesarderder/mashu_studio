# 麻薯微信连接

微信 ClawBot 消息按原文送往麻薯主脑。主脑的主对话消息和需要用户处理的上报进入微信发送队列。微信发送 `/new` 会调用主脑的新会话操作，切换后的会话不会携带上一段对话上下文。

首次使用时，先在微信中向机器人发一条消息，让桥接取得该会话的回复令牌。发送队列保存在 `~/.mashu-weixin/bridge.db`，按顺序发送，每条至少间隔 3 秒；遇到失败会退避重试。3 秒是本地设置，并非微信公开的限额。需要用户确认的上报若已处理，排队中的通知会跳过。

服务由麻薯的 `start.sh` 管理，运行在麻薯 tmux 会话的 `weixin` 窗口中。启动或停止麻薯时，微信连接随之启动或停止。麻薯开启自动启动时，微信连接也随麻薯启动；桥接进程异常退出后会自动重试。日志在 `~/.mashu-weixin/bridge.log`。绑定凭证位于 `~/.mashu-weixin/account.json`，请勿分享。

查看运行状态：`tmux list-windows -t mashu-studio`，其中 `weixin` 是连接窗口。


支持接收微信图片、文件、视频和语音，附件保存到麻薯的上传目录。微信提供语音转写时会一并转交；语音原文件保留微信提供的编码。主脑回复里的本地 Markdown 附件会发送到微信，图片和视频按对应媒体类型发送，其他文件（包括音频文件）按附件发送。单个附件上限 50 MB。

若微信没有提供媒体地址或解密密钥，麻薯会收到失败说明。网络在微信接收发送后、桥接记录成功前中断时，重试可能导致重复消息。

## 额度（2026-11-19）

ClawBot 不能无限主动推送：用户发一句后，机器人最多主动发约 10 条，超了微信返回 `-2` 拒收（平台限制）。桥接按额度发：
- 计数在 `bridge.db` 的 state `sent_since`，用户每发一条消息清零。
- 排队的纯文字短消息合并成一条发（不超过 1200 字），一条额度带走多条。
- 第 10 条额度留给提醒「微信额度快用完了，还有 N 条在排队。回「1」继续接收」。
- 遇到 `-2` 不算失败、不丢消息，停发等用户回话。
- 用户在微信发「1」/「继续」一律只用来续订额度，不转给主脑、不回复（省 token）。
- 等用户处理的上报（请示、申请、审批）精简成一条卡片（正文 500 字内、附件只留名字、带选项），排在聊天消息前面先发；每 60 秒核对一次，没送到的（含以前被额度拒掉的）自动补发。
- 重启桥接别用 `pkill -f bridge.py`（会连外层重启循环一起杀掉）；杀 python 进程本身，或 `./start.sh auto` 补回 weixin 窗口。
